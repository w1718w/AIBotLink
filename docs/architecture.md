# 架构与契约

AIBotLink 使用单进程 TypeScript 网关收发官方 QQ 消息。Codex 通过独立 stdio App Server 接入；DSH 通过外部桥接端接入，网关只依赖 [DSH Host 桥接接口](dsh-bridge-protocol.md)，保留独立 ACP 兼容路径。管理命令直接执行确定性 handler，普通任务交给原生 Agent。没有公网控制台、跨机器调度或模型 API 代理。运行依赖、接口版本与能力边界见 [兼容性与边界](compatibility.md)。

## 组件边界

| 组件 | 责任与入口 |

| 持久状态 | [state.ts](../src/state.ts)：聊天绑定、后续 Turn 设置、近期消息去重、提交状态、待交付最终回复和最近任务计时 |
| 实例所有权 | [lock.ts](../src/lock.ts)：QQ/console 本地单实例锁、持有者释放与显式清理失效锁 |
| 网关 | [gateway.ts](../src/gateway.ts)：单一命令注册表、授权、路由、任务映射和审批/提问 |

## 数据流与会话归属

QQ 私聊及群 @ 消息先检查白名单，再按消息 ID 去重。聊天作用域由机器人 App ID、私聊/群标识和用户 OpenID 构成；群内不同授权用户各自绑定会话。每个作用域保存当前 Agent，并分别保存各 Agent 的原生会话 ID。切换 Agent 不删除历史。

命令从注册表直接调用网关或适配器；入口按聊天作用域串行处理提交和命令，不等待模型整个回合结束，因此任务运行时仍可接收 Stop 和审批。普通文本先恢复/创建所选原生会话，再登记提交状态并调用原生接口。任务按 `Agent ID + 原生会话 ID` 映射回来源聊天，同一原生会话不能同时接收网关内两个聊天的任务。进度与最终回复经来源回复通道返回；进度每个任务最多两次，并有时间间隔。

命令注册表同时声明精确别名；默认完整消息“交接”执行 `/release` 同一 handler，不转交模型。别名只做整条文本去除首尾空白后的匹配，不匹配较长自然语言中的关键词。别名文案与其他产品文案一样可由本地配置覆盖。

stdio 后端由网关自己启动；DSH Host 桥连接已运行的原生 Host，不创建第二个 Agent Host。原生数据仍由 Codex/DSH 保存，网关不扫描或改写私有会话文件。Codex 历史恢复不等于接管 Desktop 活动线程；DSH 桥复用原生 Host 内会话，不构成跨 Host 抢占。网关不提供跨客户端共同控制。

`/fork` 在无待处理任务时调用原生分支接口并绑定返回的新会话。Codex 读取源线程元数据后调用 `thread/fork`，不先恢复源线程或获取其写锁；保留原生返回的历史与设置，分支不会归类为可重建的未提交空白线程。DSH Host 桥调用原生 `session/fork`，ACP 路径明确不支持。原会话不删除。

绑定原生会话 ID、后端加载会话、会话有活动任务是不同状态。`/status` 的已加载/未加载依据本网关适配器的会话记录，不代表 Desktop 是否可写或全系统锁状态。释放自己的后端只能让出本网关持有的会话，不能保证其他客户端立即接管。

Codex 恢复接口返回已识别的原生活动写者冲突时，适配器映射为明确的占用提示，网关提供新会话入口。恢复发生在任务登记和 `turn/start` 之前，因此该冲突不提交任务、不创建未知结果占位，也不改原会话历史。其他协议错误保持独立，不仅凭通用错误码猜测写锁。解除外部占用必须由占用方处理，本网关 `/release` 不能解除其他客户端的锁。

## 生命周期与恢复

网关初始化仅建立适配器对象，命令或任务按需启动 stdio 后端或 Host 桥连接。一个接入失败不要求另一个 Agent 存活。`/stop` 使用任务记录中的原始 Agent/Session 中断任务；`/runtime stop` 关闭自建后端或桥接客户端，桥接模式不停止 Desktop。

`/release` 是当前所选 Agent 的空闲交接操作。stdio 模式停止该 Agent 整个自有后端，影响其所有聊天中加载的会话，不执行单线程卸载；DSH 桥接模式只断开网关客户端，不停止 Host，也不承诺 Host 卸载会话。该实例有活动网关任务、非 `completed` 提交记录（包括未知结果）或待审批时拒绝；存在其他正在处理的命令/提交时也拒绝，交接窗口中新输入提示稍后重试。

Codex 释放前使用原生 loaded 列表及线程状态确认所有已加载线程空闲，原生压缩等仍活跃时拒绝。已知从未提交输入的空白线程没有 rollout 时允许继续停止，但会清除此类不可恢复绑定。已有原生历史、其余会话绑定、后续 Turn 请求设置及待交付结果保留，不删除会话文件。下一次文本或原生会话查询可按需启动/恢复；其他客户端已持有会话时依原生接口报冲突，不抢回控制。

QQ 和本地终端模式在读取运行状态前取得同一数据目录的排他锁，避免多个实例竞争写入。锁含进程 PID 和随机持有者标识；退出时仅释放自己持有的锁。显式 `unlock` 只在记录 PID 不存在时删除失效锁，无法确认或进程仍活着时拒绝，绝不按锁文件中的 PID 终止进程。`doctor` 创建独立的后端或桥接连接，不读写 `StateStore`，不把运行实例的任务误标为未知；Host 桥只允许一个客户端，已占用时连接可能被拒绝。

stdio 协议客户端持有实际 ChildProcess；关闭时先结束 stdin，超时后终止自己的进程，Windows 按该进程 PID 终止进程树，不按可执行文件名查杀。Host 客户端关闭自己的连接；断线不自动取消已进入原生 Host 的任务，网关按未知结果处理。不提供附加已运行 Codex 后端或系统服务安装功能；登录自启由计划任务脚本提供，不等同系统服务。

## DSH Host 桥

网关与 DSH 之间只通过 [DSH Host 桥接接口](dsh-bridge-protocol.md) 通信：桥接端在仓库外写入包含回环地址与 Token 的连接记录，网关读取记录后建立认证 HTTP RPC 和一条 SSE 事件连接。接口不绑定具体实现，桥接端负责与原生 Host 交互、任务归属和交互适配；网关不包含桥接实现，也不启动或停止 Host。连接记录是凭据，不能提交 Git。

网关侧只消费接口语义：会话创建、恢复、列表、历史、分支、模型与推理选项、权限目录与执行、任务提交与中断、Steer、压缩，以及审批/提问请求。事件按会话归属过滤，任务按本网关提交映射回来源聊天；不把 Desktop 无关回合当成网关回复。接口不可用或断开时，网关按未知结果处理，不自动取消原生任务、不重放；具体字段与错误语义以接口文档为准。

仓库中的可选 `npm run install:dsh` 便捷脚本默认通过 DSH 原生插件 CLI 从 GitHub 安装桥接端，保留 `AILINKBRIDGE_COMPANION` 本地目录覆盖。它依赖 Windows 标准 DSH 安装位置及已有配置和 Profile，备份 Profile 清单与网关配置、启用 bundle 并更新 `dshBridge`；不启停 Host。安装与配置步骤见 [项目 README](../README.md#dsh-host-桥接)。桥接端的分发、注册和 Host 重启不属于接口契约。

本地 `state.json` 保存绑定、近期已处理消息、提交状态、待交付最终回复和面板标记，不保存完整聊天历史。提交状态为 `dispatching`、`accepted`、`unknown` 或 `completed`。重启将未完成状态标为 `unknown`，保留已完成状态及结果；断线或调用失败也可能产生未知结果。

原生任务结束后先将最终回复写入 `responses` 并标记 `completed`，再向来源聊天发送，交付成功后删除该结果与操作记录。交付失败或此时重启仍可用 `/result` 显式取回，重新发送的只是保存结果，不是 Agent 任务。未知结果需用户在原生端核验后 `/ackunknown`；有活动、未知或待交付操作记录时，不接受新的普通任务。没有自动重放，也不保证端到端恰好执行或交付一次。

## 设置与交互

Codex 模型/推理值由原生目录校验，保存为后续 `turn/start` 的请求参数；本地可选模型配置只作用于新建线程，不改全局配置。DSH ACP 使用原生 `configOptions`；DSH Host 桥接接口要求桥接端返回同一选项契约，并在查询时刷新。Host 桥的模型/推理修改经接口的 `session/set_config_option` 返回新选项，原生实现可能同步保存默认选择，不能承诺仅影响当前会话。两种路径都不自行重写原生配置或强制切换提供方。

提供方默认沿用原生配置。提供方查询从 Codex 会话/配置或 DSH 原生模型分组取得目录；选择当前提供方不改变原生设置，跨提供方时 Codex 使用原生重新配置路径，DSH 选择对应模型组首项。返回后更新会话绑定并清除网关后续 Turn 设置。兼容性与边界见 [兼容性](compatibility.md)，目录不证明账号认证和模型权限。

Codex 权限修改仅接受用户显式选择的 `read-only`、`workspace-write`，使用原生响应确认沙箱及 `on-request` 审批策略，拒绝运行中设置。Codex 0.153.2 的未产生 rollout 空白线程无法恢复；适配器只为本进程创建且从未尝试提交输入的线程新建替代线程，继承已知的工作目录、模型、提供方、沙箱和审批策略，并更新聊天绑定。已有历史始终调用原生恢复接口；尝试提交输入前就撤销空白标记，超时后不重新当作空白处理。无法保留原生策略时明确失败，不静默放宽权限。

受支持的原生审批/提问通过随机令牌映射到原始请求、Agent、Session 和来源作用域，十五分钟有效；不自动批准。Codex resolved 事件、任务结束或后端断开会撤销相关交互。未知请求返回不支持，未冒充成功。具体类型见 [兼容性](compatibility.md)。

QQ 回调按钮校验用户、群、作用域和有效期，执行前消费令牌并 ACK。普通菜单按钮另校验生成时的 Agent/Session 选择，前台已切换目标时旧按钮失效。审批/回答按钮通过不可变令牌映射原始请求，不依赖当前前台 Agent，避免切换后无法回答原任务。按钮每行一项，标签与帮助描述由同一命令注册表派生，标签使用独立短文案。交互规则见 [兼容性](compatibility.md)。

原生列表超过四项时，网关将剩余会话及原生下一页游标放入按聊天作用域、Agent 归属校验的十五分钟内存缓存，逐页显示四项。缓存重启后失效，不保存进本地状态；它不改变原生会话或历史。

`timings` 仅为每个聊天保留最近一次有计时结果的分段数字及模型/推理值，不保存新的任务正文或长期遥测日志。`/status` 展示准备、后端、首字、回复发送与合计耗时；首字相对于后端任务开始，属于重叠观测值，不能把各项简单相加。发送失败时发送耗时可能缺失，已有任务不会被追溯补测。

## 配置与权限边界

配置、状态及 SDK 数据使用仓库外数据目录。DSH 导入只保存凭据文件引用；密钥读取后用于 SDK，不写入仓库。用户白名单必填；群消息还需群白名单。进程命令来自本地配置，聊天不提供任意远程 Shell。

同一 QQ App ID 的消息接收端应保持唯一，旧 dsh-im QQ 连接及其他桥接实例需停用，避免重复执行或回复。网关单实例锁只约束同一数据目录，不能替代不同程序、不同数据目录之间的部署排他。机器人显示名称不用于选择或识别原生后端。

QQ C2C 面板从同一命令注册表生成固定常用入口，最多二十项，包含完整菜单、帮助、分支和交接；只更新带本网关标记的面板，内容相同时不重复更新。`/m` 提供所有命令，每页最多八个入口，按钮按两列四行排列；翻页按钮另占一行，因此消息最多五行。必填参数入口先提供用法。同名命令供两种 Agent 共用，能力差异由执行路径提示。默认短标签不超过三字、备注不超过十字，面板备注使用同一描述并截断超长覆盖值。全局菜单保留无关条目；同步失败保留文字命令。当前未接文件传输，不因回答含本地路径而外发文件。

## 文案与兼容边界

默认产品文案集中在中文 JSON 资源，`messages.ts` 校验本地覆盖键并替换模板参数。命令说明和短标签共用注册表，帮助与 QQ 交互不各自硬编码。当前只有中文，不声明完整 i18n。未知覆盖键会报错，不静默忽略。

原生协议异常仍快速失败；针对 DSH 0.2.1-rc.2 的 stdout 诊断前缀，由标有 `COMPAT` 的精确规则处理，源码保留适用版本和移除条件，不泛化为任意文本兜底；该规则只用于 DSH ACP stdio 路径，不适用于 [DSH Host 桥接接口](dsh-bridge-protocol.md)。独立推理脚本标为 `TEST_ONLY`，测试假标识与故意缺失后端标为 `TEST_FIXTURE`，它们不属于生产路由或默认配置。

桥接端是实现本接口的外部组件，其许可证、第三方代码归属和适用范围由该实现自行说明；网关仓库不包含桥接端代码，也不因其参考过其他项目而沿用其 IM 结论。
