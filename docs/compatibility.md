# 兼容性与边界

本页说明运行依赖、接口版本、能力边界与配置约束，不记录测试进度或个人运行状态。

## 运行依赖

| 项目 | 约束 |
|---|---|
| Node.js | >=22.19；依赖版本由 package.json 与锁文件定义 |
| Codex | 通过 stdio App Server 接入，使用原生会话、模型、权限和工具接口 |
| DSH | 支持 Host 桥接接口与 ACP 兼容路径；Host 桥接端需实现 [DSH Host 桥接接口](dsh-bridge-protocol.md) |
| QQ | 官方机器人 C2C；群聊仅做白名单校验与基础收发 |
| 系统 | Windows 单机；安装位置由使用方决定，其他系统与多机部署不在支持范围 |

## 接口与版本边界

- DSH Host 桥接接口的连接记录版本为 `1`，初始化 `protocolVersion` 为 `1`；桥接端按 `1` 返回，协议升级需双方同步。
- 桥接接口只接受一个认证客户端；RPC、事件流和审批响应绑定该连接。连接断开后，未确认的提交按未知结果处理，不自动取消原生任务、不重放。
- 连接记录包含回环地址与 Token，必须位于 Git 仓库外；配置、状态与日志同样必须在仓库外。
- DSH ACP 路径通过 stdio 与原生 ACP 会话通信，不提供 Host 桥接接口支持的历史、分支、Steer、Compact 和权限修改能力。

## 能力边界

| 范围 | 行为与限制 |
|---|---|
| 消息 | 仅文本；不转交附件，不回传本地文件 |
| 群聊 | 仅白名单校验与基础收发；不提供群管理或其他 IM 接入 |
| 历史 | `/history` 只取 Codex 最近五个 Turn，或 DSH Host 最近快照中的真实用户与助手消息，不含注入的 workspace 指令、runtime context 等上下文；不提供完整历史翻页 |
| 分支 | `/fork` 对 Codex 与 DSH Host 桥调用原生分支接口；DSH ACP 路径不支持 |
| 会话控制 | `/stop`、`/steer`、`/compact` 通过原生能力执行；DSH ACP 路径不支持 Steer、Compact |
| 权限 | Codex 提供 `read-only`、`workspace-write` 两种沙箱模式；DSH Host 桥按原生权限目录执行；DSH ACP 路径不支持权限修改 |
| 审批与提问 | 支持原生审批/提问的转发与回答；不自动批准，不代替 Desktop 的原生回答 |
| 跨客户端 | 不附加已运行 Codex 后端，不提供 Desktop 或其他客户端的跨客户端共同控制；`/release` 只释放网关自己的后端或连接 |
| 交接 | 空闲时可停止网关自有后端；Desktop 是否接管由原生客户端决定，网关不抢锁 |
| 未知结果 | 提交超时、断线或原生任务状态不明时按未知结果处理；用户需在原生端核验后使用 `/ackunknown`，网关不自动重放 |
| 安装 | 安装位置由使用方决定；配置、状态、日志和连接记录必须在仓库外 |
| 系统集成 | 仅 Windows 单机；不提供系统服务安装；登录自启由计划任务脚本提供 |

## 原生设置与会话边界

模型目录或配置中存在某个模型，不证明当前账号有调用权限。默认提供方跟随原生配置，不为绕过认证失败自动替换提供方；`/provider` 不负责修复账号凭据。DSH Host 桥的模型/推理选择经桥接接口完成，原生实现可能同步保存默认值，不能承诺只影响当前会话。

Codex 恢复接口返回原生活动写者冲突时，适配器返回明确的占用提示，本次任务不提交，也不修改原会话历史。解除外部占用必须由占用方处理，`/release` 不能解除其他客户端的锁。

Codex 0.153.2 未产生 rollout 的空白线程无法恢复。网关只为本地创建且从未尝试提交输入的空白线程新建替代线程，并继承已知的工作目录、模型、提供方、沙箱和审批策略；已有历史的线程始终走原生恢复接口。任何提交尝试之后都不再按空白线程处理。

DSH ACP 的空白会话关闭后可恢复，但设置可能恢复为默认值；该路径不提供图片、音频或嵌入上下文输入。所有接入只转交文本。

`/history` 返回 Codex 最近五个 Turn，或 DSH Host 最近快照中的真实用户与助手消息，不含注入的 workspace 指令、runtime context、skill catalog、time context 等上下文；不提供完整历史翻页。目录可分页不代表所有历史记录都能一次读回。

## 开发者测试

网关在仓库根目录执行：

```powershell
npm ci
npm run build
npm test
```

`npm test` 先构建，再运行 `dist/test/*.test.js`。测试使用假 stdio、HTTP/SSE 和假 Host，不连接 QQ 或模型，也不访问桥接端实现。

显式运行的 `scripts/smoke-native.mjs` 标为 `TEST_ONLY`，会调用原生模型测试；`scripts/probe-controls.mjs` 查询原生目录、当前提供方及 Codex 沙箱控制，不启动推理。两者都不由启动流程自动执行。

`TEST_FIXTURE` 标记假账号和假协议数据，不进入生产配置。`COMPAT` 精确匹配 DSH 0.2.1-rc.2 的 stdout 诊断前缀，只用于 DSH ACP stdio 路径，其他非协议输出仍快速失败。只有中文文案资源与仓库外本地覆盖，不提供完整 i18n。
